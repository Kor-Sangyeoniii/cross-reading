# Cross Reading 앱 구성 기획안

2026-10-14 KST · 논의용 v0.2 · 사용자 요청에 따른 제품 구성 제안

## 1. 제품 한 문장

나를 알아가는 사주 캐릭터와, 생활 조건이 맞는 사람을 실제로 알아가는 소개를 연결한다.

사주·캐릭터는 자기 탐색과 대화의 계기다. 소개 후보는 상호 선호, 넓은 생활권, 만날 수 있는 시간, 관계 목적, 활동 의사로 고른다. 사주나 외모로 인품·안전·궁합을 점수화하지 않는다.

## 2. 화면 구조

| 하단 탭 | 처음 보이는 내용 | 눌러서 확인하는 내용 | 대표 행동 |
| --- | --- | --- | --- |
| 오늘 | 오늘의 풀이 한 문장, 진행 중 소개·결제 상태, 새 메시지 | 선택 날짜의 해석 근거·일상 예시 | 오늘 풀이 보기 / 이어서 진행 |
| 내 사주 | 내 캐릭터, 일주 이름, 기질 요약 | 기질·오행·십성·일/월/연간 흐름·대운 | 관심 주제 선택 / 익명 공유 |
| 소개 | 실제 사진, 닉네임, 넓은 생활권, 관계 목적, 겹치는 시간 | 소개 이유, 생활 취향, 참고용 관계 해석 | 무료 관심 보내기 |
| 대화 | 서로 관심·결제 대기·대화 중 상태, 읽지 않은 메시지 | 결제 기한·환불 상태, 대화방, 신고·차단 | 대화하기 / 상태 확인 |
| 마이 | 소개 참여 여부, 내 프로필, 계정 | 인증 상태·알림·결제/환불·지원·개인정보 | 소개 잠시 쉬기 / 프로필 수정 |

첫 화면에는 한 문장 요약과 지금 할 행동을 둔다. 상세 풀이는 주제를 누르면 펼친다. 새 메시지·결제 기한·환불 오류처럼 후속 행동이 필요한 상태를 긴 운세 본문보다 앞에 배치한다. 기존 친구방은 대화 탭의 별도 필터로 접근하고 소개팅 결제를 적용하지 않는다.

## 3. 처음 들어온 사람의 이용 순서

진입 → [내 사주 보기 / 소개받기] → 가입·로그인 → 선택한 목적에 필요한 정보만 입력.

- 로그인: 아이디·비밀번호를 기본 진입에 명확히 표시한다. 계정이 없으면 가입, 연결이 검증된 소셜 로그인만 노출한다. 계정 복구 경로를 제공한다.
- 개인 사주: 출생정보 입력, 태어난 시간 모름 허용, 캐릭터와 풀이 열기. 상대에게 출생 원본을 공개하지 않는다.
- 소개 참여: 성인·본인 확인, 사진 검토, 넓은 생활권, 가용 시간, 관계 목적, 상호 선호, 소개 참여 동의. 실제 인증 연동 전에는 실제 소개 참여를 열지 않는다.
- 사주 입력은 소개의 필수 조건으로 두지 않는다. 입력하지 않아도 생활 조건으로 소개받도록 설계한다.
- 사용법: 한 사람 시점의 짧은 안내. 소개 카드 확인 → 무료 관심 → 예시 상대 응답 → 가상 결제 → 대화. 모든 자동 응답과 결제는 예시라고 표시한다. 4인 전환 도구는 고급 테스트에 둔다.

## 4. 내 사주 상세

주제 버튼: [내 기질] [오행 흐름] [십성] [일별] [월간] [연간] [대운].

각 상세는 ‘요약 → 해석 근거 → 구체적인 상황 → 내가 선택할 행동’ 순서다. 비견·겁재 등 용어는 쉬운 설명을 먼저 보여주고 원래 용어를 보조 표기한다. 하나의 요소로 사람을 단정하지 않는다.

예시 문장 형식: “자기 기준을 지키려는 면으로 읽어볼 수 있어요. 약속 장소를 정할 때 선호를 먼저 말하되, 상대가 원하는 조건도 하나 물어보세요.” 실제 개인 문장은 계산 결과에 연결하고 근거 없는 공통 문구를 개인화 결과로 보여주지 않는다.

- 날짜 선택: 선택한 날짜·기간, 기준 시간대와 달력 기준을 표시한다. 일별 결과와 월·연간 흐름을 구분한다.
- 오행: 상생·상극 관계 그림의 오행을 누르면 뜻, 관측한 글자 수, 해석 한계를 보여준다. 개수는 강약·성격 점수가 아니다.
- 시간 모름·절기 경계는 계산 불확실성을 알린다. 필요한 데이터와 계산 규칙을 확인하기 전 대운 시작 나이 등을 만들어 보여주지 않는다.
- 대운은 기간별 목록과 현재 구간 상세로 표현한다. 건강·재산·연애 결과를 확정하거나 불안을 유도해 결제시키지 않는다.

## 5. 캐릭터 규칙과 임시 이미지

현재 생성한 불 원숭이는 아트 방향을 보는 임시 시안이다. 양산·최종 UI 적용은 별도 단계다.

- 몸체: 일지의 십이지 동물. 출생 연도의 띠와 구분해 설명한다.
- 기본 변신: 일간의 오행. 화는 치솟는 갈기와 격한 표정, 목은 가지·잎과 차분한 실루엣처럼 외형 자체에 차이를 준다.
- 보조 표현: 사주 전체 오행 분포를 추가 문양·빛·설명으로 표현하되, 기본 일간이 바뀐 것처럼 보이게 하지 않는다. 동률·시간 모름을 표시한다.
- 병신(丙申)은 화 일간 + 원숭이 일지. “불이 많은 금 일간”은 별도 조합이며 병신과 혼동하지 않는다.
- ‘분노한 불 캐릭터’는 미술 설정이지 사용자가 공격적이라는 판정이 아니다. 인증·소개 노출·제재와 연결하지 않는다.
- 일주 조합은 60개. 처음부터 최종 일러스트 60장을 제작하지 않고 같은 동물의 화/목 시안으로 차별성을 확인한 후 기본 동물과 효과를 확장한다. 효과 합성만으로 최종 품질이 충분한지는 검증한다.
- 실제 소개 카드는 본인의 검토된 사진을 중심에 둔다. 캐릭터가 사진·인증을 대신하지 않는다.
- 공유는 캐릭터와 사용자가 선택한 설명만 내보낸다. 실명·생년월일·시간·상대 정보는 기본 제외. 일주도 공개 정보가 될 수 있어 공유 전 표시 항목을 미리 보여준다.
- 로딩: 1~2초 내 가벼운 눈빛/오행 효과. 처리가 끝나면 즉시 넘어가며 연출 때문에 지연시키지 않는다. 동작 줄이기 설정을 따른다.

## 6. 소개 상세의 정보 순서

1. 실제 사진·닉네임·넓은 생활권·관계 목적.
2. ‘소개한 이유’: 양쪽이 입력한 가능한 시간, 선호 활동, 생활권의 교집합.
3. ‘함께 맞추기 쉬운 점 / 먼저 이야기할 점’: 생활 조건과 대화 선호를 근거로 구체적 설명.
4. 선택해서 여는 ‘사주로 보는 관계 이야기’: 참고 해석과 근거, 첫 대화 질문. 궁합 점수나 좋음/나쁨 확정 판정 없음.
5. ‘관심 보내기 · 무료’ / ‘이번 소개 넘기기’.

후보가 없으면 대기 이유와 내가 변경할 수 있는 선호를 안내한다. 적격 후보를 만들어 채우거나 만남을 보장하지 않는다. 프로필 열람·관심 표시·이미 열린 대화에 반복 과금하지 않는다.

## 7. 반반 결제와 환불

제안 모델은 ‘상호 관심이 확인된 연결 1건의 고정 비용을 두 사람이 절반씩 부담’이다. 월 구독으로 무조건 소개를 보장하는 모델과 혼합하지 않는다. 금액은 미정. 기존 체험의 각 3,000원은 가상 예시이며 확정 가격이 아니다.

| 상태 | 사용자 화면 | 처리 원칙 |
| --- | --- | --- |
| 한쪽만 관심 | 상대 응답 기다리는 중 | 결제 요청 없음 |
| 서로 관심 | 총 연결비·내 부담·개설 조건·환불 조건 | 동의 후 결제 |
| 첫 결제 완료 | 내 결제 완료 / 상대 결제 대기 / 종료 시각 | 첫 결제부터 24시간을 제안값으로 사용 |
| 양쪽 결제 확인 | 대화 시작 | 서버 확인 후 한 번만 개설 |
| 한쪽 미결제로 기한 만료 | 연결 종료 / 환불 처리 중 | 먼저 낸 금액 전액 환불 절차 시작 |
| 환불 오류 | 환불 지연 / 접수 내역 / 지원 연결 | 재처리, 성공 전 완료 표시 금지 |
| 환불 확인 완료 | 환불 완료 / 결제 수단 반영 안내 | 실제 반영 기간은 결제사 기준 |

미개설 상태에서 취소·차단·운영 중단으로 연결이 종료되면 납부금은 환불 대상으로 처리한다. 기한 경계에 늦게 도착한 결제도 대조하고 환불 대상으로 처리한다. 결제 페이지 복귀만으로 성공 처리하지 않는다.

결제는 응답이나 실제 만남을 보장하지 않는다. 개설 이후 취소·무응답·신고 건의 환불은 출시 전 약관과 운영 정책으로 확정해야 한다. 다른 연결에 추가 비용이 생기는 경우 결제 전에 명확히 알린다.

## 8. 알림과 안전 운영

- 앱 안: 하단 대화 배지, 방별 읽지 않은 수, 새 메시지 도착 표시. 내 결제와 상대 결제 상태를 혼동하지 않는 알림.
- 웹 푸시: 기능을 이해한 뒤 사용자가 켜기. 지원 환경·권한·설치 조건 확인, 토큰 만료/재등록/중복 발송 검증. 거절해도 앱 안 알림은 작동. 잠금화면 메시지 본문은 기본 숨김.
- 성인·본인·사진 확인은 각각 실제 확인 범위만 표시한다. 확인 배지가 범죄 무이력이나 신뢰 보증이라는 인상을 주지 않는다.
- 금전 요구·투자 유도·급한 외부 메신저 이동 등 관찰 가능한 위험 행동을 경고하고 신고/차단을 항상 제공한다. 규칙 오탐과 우회가 있으므로 100% 차단을 약속하지 않는다.
- 일정 기간 활동 의사 미확인은 추천에서 숨기고 재확인으로 복귀한다. 기존 제안은 7일이며 정책값이다. 무응답·미결제만으로 자동 탈퇴하지 않는다.
- 신고 접수 → 즉시 차단 등 사용자 보호 → 위험도에 따른 검토 → 근거가 있는 제한 → 당사자 통보/이의제기. 신고 접수만으로 영구 제재하지 않는다.
- 운영 화면: 신고 대기, 인증/사진 검토, 제한/이의제기, 환불 실패, 접근 감사. 출시 범위에 포함한다.
- 계정 삭제와 결제·신고 기록의 보존 범위/기간은 법적 근거와 정책을 확인해 설계한다. 개인 입력, 메시지, 인증 원본, 비밀키를 진단 로그에 남기지 않는다.

## 9. 출시 순서와 통과 기준

| 단계 | 범위 | 완료 판단 |
| --- | --- | --- |
| 1. 구성 검토 | 이 기획안, 탭/상세 구조, 임시 캐릭터 | 첫 사용자가 어디를 눌러야 하는지 설명할 수 있음 |
| 2. 일관된 사용 흐름 | 한 사람 체험, 개인 사주 상세, 소개 근거, 새 메시지 표시 | 도움 없이 소개→상호 관심→가상 결제→대화, 환불 이해 |
| 3. 실제 소규모 운영 준비 | 인증/사진/결제, 서버 연동, 운영 화면, 환불/알림/탈퇴 | 실제 연동·권한·실패 복구 검증, 정책과 운영 책임 확정 |
| 4. 제한 모집 | 한 생활권·소수 참여자 | 후보 공급, 상호 관심, 결제 후 첫 대화, 환불 지연·신고 대응 측정 |
| 5. 확장 | 검증된 캐릭터 양산·익명 공유·지역 확대 | 이용 지속과 운영 부담을 함께 확인 |

가격·기간·공급 규모는 가설이며 매출이나 바이럴 효과를 검증했다고 주장하지 않는다. 개발 일정/외부 비용은 실제 연동 범위와 계약 조건 확인 후 산정한다.

## 10. 승인 당시 구현과 제안의 경계

저장소 문서 기준 기존 공개 테스트에는 개인 풀이·로그인·친구 대화와 4인 합성 소개 체험이 있고, 현재 작업 브랜치에는 한 사람 안내와 오행 조합 UI가 미커밋 상태로 있다. 이번 기획의 5탭 통합과 십이지 변신 캐릭터 체계 전체가 구현됐다는 뜻은 아니다.

실제 소개용 인증/사진 검토/PG/운영 화면·환불 작업 연동은 남아 있다. 실제 소개팅 회원과 거래가 운영 중이라고 표현하지 않는다. 이 기획을 승인받은 시점에는 문서와 클릭 가능한 구성 시안만 작성했다. 승인 후 구현·검증·배포 상태는 05-guided-usage.md에서 별도로 기록한다.
