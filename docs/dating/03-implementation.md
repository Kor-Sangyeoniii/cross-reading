# 구현·운영 인수 문서

## 지금 실행 가능한 것
- `/dating`: 소개팅 방향과 실제 서비스 준비 상태. `/dating/demo`: 로그인 없는 4인 합성 체험.
- 소개 이유, 상호 호감, 동의 후 반반 가상 결제, 24시간 만료, 환불 처리 중/실패/완료, 대화·새 메시지 표시, 링크 제한·금전 경고, 신고·차단, 7일 활동 확인, 가상 운영 검토·이의제기.
- 개인정보를 저장하지 않도록 체험 상태는 React 메모리만 사용. 새로고침/경로 이탈로 제거. 실제 Supabase 계정이나 서버 인증 배지가 아니다.
- 기존 개인 운세·프로필·로그인·친구 대화는 기존 경로로 유지. 화면 연결과 도메인 코드에 실제 결제 SDK/비밀키 없음.

## 서버 구현
`20261013000001_dating_pilot.sql`: 9개 RLS 테이블, 20개 RPC/내부 함수. 인증 회원은 승인된 RPC만 호출. 회원 프로필 직접 update/타인 조회 금지, 결제 원장·운영 메모·설정은 service_role만 접근. 서로 관심·성인/사진 검토·활동·차단·공급 조건은 서버 검사.

- `dating_config.enabled=false` 기본값. 사용자 UI에 실제 기능을 켜는 플래그나 버튼이 없음.
- `dating_create_order`: 연결 잠금, 두 사람 관심 확인, 서버 단가 스냅샷, 참여자 주문만 반환.
- `dating_record_payment`: 서버 전용, 동일 결제 중복 안전, 먼저 결제 확정 시 기한 시작, 양쪽 승인 시 개설. 지연 도착한 결제는 환불 대상으로 전환.
- `dating_expire`: 기한 경과 연결 잠금·종료·환불 대기 표시. 실제 배포 시 스케줄러가 실행해야 함.
- `dating_settle_refund`: 조회 확인된 결과만 기록. 실패/완료 분리. 호출만으로 PG 환불이 발생하지 않음.
- `dating_send`: 개설된 방의 당사자만, 제한·차단·서비스 중지 시 발송 금지. 읽기 접근은 당사자만 유지해 신고 근거 확인 가능.
- `dating_report`는 자동 제재를 하지 않음. `dating_review`와 `dating_restore`는 운영자 식별자·근거 기록 필수. 대상에게 공개 사유만 보여주고 신고자/내부메모는 숨김.
- `src/lib/dating.ts`: 실사용 화면에서 사용할 RPC 클라이언트 경계. 현재 체험에서는 호출하지 않음.
- `src/core/datingProvider.ts`: 제공자 조회 결과의 주문·사용자·상점·금액·통화 검증 및 환불 대조 코드. 서명검증/서버 HTTP 클라이언트가 이 경계를 호출해야 하며 브라우저 반환값을 넣으면 안 됨.

## 실제 출시 전 남은 연동과 운영 조건
아래는 구현 완료로 포장하지 않는다. 이번 작업에서 서버 마이그레이션을 운영 DB에 적용하거나 실제 회원/금액을 처리하지 않았다.

1. 인증·사진 확인 업체 선택/계약 및 적용 가능한 필드 확인. 성인확인 결과를 갱신하는 서버 연동, 인증 만료 정책. 인증 원본/CI·DI 저장 여부는 필요성과 법적 근거 검토 후 결정.
2. PG 소개팅 업종 승인·수수료·취소 정책 확인. 실제 SDK와 서명검증 웹훅/서버 조회 어댑터 연결. 이 문서의 provider 인터페이스는 업체 통신 구현이 아님.
3. 만료 스케줄러와 환불 작업 큐/임대(lease), 실패 경보·대조 운영. 동시 워커·잠금 경합은 실제 PostgreSQL 다중 연결 부하 검증 추가. PGlite는 SQL/RLS 기능 검증이며 동시 실행 증명 아님.
4. 실제 회원 온보딩(사주 선택형·사진/동의), 인증된 운영자 콘솔, 접근 감사·통보, 메시지 신고 증거와 보존 정책. 가상 운영자 체험은 실운영 관리화면이 아님.
5. 법률·개인정보·환불·탈퇴 정책 및 외부 벤더 리뷰. 기존 `delete-account`는 auth.users를 바로 삭제하므로 신규 원장의 보존/정산과 충돌. 새 마이그레이션 FK가 삭제를 차단하도록 두었고 적용 전에 탈퇴·비식별화·보존 절차를 별도로 구현해야 함. 조용히 결제·신고 기록을 cascade 삭제하지 않음.
6. 상용 호스팅으로 이전. 기존 Pages는 승인된 합성 체험/테스트 게시만. 최신 경쟁사·법령 원문, 실제 수요와 가격 수용성은 아직 검증 전.
7. service_role/PG/인증 비밀값은 환경의 보안 설정으로 제공. 채팅·코드·로그에 넣지 않음. 현재 필요한 키는 연결되지 않았으며 실제 테스트 계정 생성도 여전히0개.

## 로컬 검증
```sh
cd /workspace/cross-reading
npm ci --cache /tmp/cr-npm-cache
npm test
npm run test:dating-db
npm run lint
npm run build
npm run dev -- --host 127.0.0.1
# 다른 세션에서. Playwright 경로가 다르면 CR_PLAYWRIGHT_MODULE로 지정.
npm run test:dating-browser
node scripts/verify-home.mjs
node scripts/verify-password-auth.mjs
```

브라우저 스크립트는 외부 요청을 차단하며 캡처를 생성하지 않는다. DB 스크립트는 WASM PostgreSQL에 가짜 auth 역할/UUID를 만든 뒤 마이그레이션 원문과 실제 SQL/RLS를 실행한다. 운영 환경으로 연결하지 않는다.

## 혼자 체험하는 순서
1. 모리 → 타오 소개 → 관심 보내기.
2. 위쪽 타오로 전환 → 모리 → 나도 관심 있어요 → 조건 확인 → 가상 결제.
3. 모리로 전환 → 타오 → 가상 결제. 이제 대화가 열림. 인물 전환으로 새 메시지 확인.
4. 새 체험에서는 한 명만 결제하고 ‘체험 도구 → 24시간 지나기’. 환불 처리 중/실패/완료를 확인.
5. 신고 접수 후 ‘지원 → 가상 운영자 검토 체험’에서 검토·제한. 해당 인물로 전환해 이의제기. 신고만으로 제재되지 않음을 확인.
6. ‘7일 지나기’로 추천 숨김, ‘내 소개 → 이번 주 소개 받을게요’로 복귀. 제한 중이면 자기 복귀 불가.
