# CR-023 — 5탭 앱과 한 사람 시점의 사용 흐름

2026-10-14 KST. 승인된 구성안: [06-app-plan.md](06-app-plan.md). Codex 작업 브랜치 `codex/CR-023-guided-dating`, PR의 기준은 CR-022다. main과 확정 정책 문서는 수정하지 않았다.

## 이번에 구현한 것

- 로그인한 계정의 하단 메뉴: 오늘 / 내 사주 / 소개 / 대화 / 마이. 소개에서도 같은 계정의 새 메시지 상태를 유지한다.
- 오늘: 실제 저장된 출생정보와 한국 날짜로 계산한 오늘의 주제, 개인 풀이 진입, 새 메시지 경로.
- 내 사주: 일지 동물 + 일간 오행 수호신. 기질·원국/십신·오행·일/월/연간·대운을 각각 눌러 연다. 이미 있던 계산/상세 근거 엔진을 재사용한다.
- 대화: 기존 친구 모임은 유지하고, 실제 소개 대화는 준비 상태임을 구분한다. 마이에서 정보·웹 푸시·계정 설정에 접근한다.
- `/try`: 로그인 없는 5탭 테스트. 합성 출생정보를 실제 계산 엔진에 넣어 날짜별로 다른 풀이와 대운을 확인한다. 개인 입력·결제·본인인증·외부 메시지 호출 없음.
- `/try` 안 소개: 별명/가능한 시간 → 추천 이유 → 무료 관심 → 예시 상대의 관심 → 조건 동의 → 가상 반반 결제 → 예시 첫 메시지. 상대 행동은 미리 정한 예시라고 명시한다.
- 탭을 이동해도 안내 상태를 유지한다. 다른 탭에 있을 때 예시 메시지가 도착하면 오늘 화면과 대화 탭에 배지가 생기고, 보이는 대화로 돌아오면 읽음 처리한다.
- `/dating/demo`: 같은 한 사람 안내를 단독으로 제공. 기존 링크를 그대로 사용한다. 미결제 대안에서 24시간 만료 → 환불 처리 중 → 환불 완료를 시험할 수 있다.
- `/dating/lab`: 기존 4인 테스트 도구. 수동 관심·결제·환불 실패/재시도·신고·차단·운영 검토·활동 휴지/복귀를 시험한다.
- `/dating`: 소개 약속·준비 상태·위 테스트 경로를 안내한다. 기존 로그인 화면에도 `/try` 진입 버튼을 추가했다.

## 캐릭터 표현

몸체는 일지의 십이지, 기본 변신은 일간의 오행이다. 병신일주는 ‘화 일간 + 원숭이 일지’이며 ‘금 일간에 화가 많은 경우’와 구분한다. 전체 오행 개수는 별도 설명이다. 동률, 시간 모름, 절기 경계, 단순 개수 해석 한계를 표시한다.

현재 완성 아트가 있는 것은 사용자가 요청해 생성한 불 원숭이 임시 시안 하나다. 일간 화 + 일지 신에만 이 이미지를 사용한다. 다른 조합은 실제 동물과 오행 이름이 맞는 임시 심볼을 표시하며, 그림을 완성했다고 표현하지 않는다. 60일 연속의 실제 계산으로 60일주와 동물 12종의 매핑을 검증했다.

앞서 작업 중이던 ‘5개 마스코트 + 장식’ UI/이미지 내보내기 초안은 사용자의 최신 십이지 방향으로 대체했으며 미사용 파일을 남기지 않았다. 분포 계산 모듈은 새 카드의 근거 표시에서 재사용한다. 익명 캐릭터 공유 카드의 새 일주 디자인과 아트 양산은 후속 범위다.

## 테스트 방법

1. `/try`에서 **내 사주** → 일별·월간·연간·대운 등을 선택한다. 날짜와 대운 계산 기준을 바꿔본다.
2. **소개**에서 별명/시간 → 상대 소개 → 관심을 보낸다. **오늘**이나 **마이**로 옮긴 뒤 **대화**에서 이어간다.
3. 결제 조건을 확인하고 가상 결제를 누른 직후 **오늘**로 이동한다. 새 예시 메시지 표시가 생기면 열고 첫 인사를 보낸다.
4. 처음부터 다시 진행해 상호 관심 단계의 ‘상대가 결제하지 않으면?’에서 미결제/환불을 시험한다.
5. 새로고침하면 가상 소개와 메시지는 초기화한다. 실제 이름·연락처·사진을 입력하지 않는다.
6. 실제 내 사주는 ‘내 계정으로 이용’에서 가입·로그인 후 확인한다. 실제 소개/결제 참여와는 별개다.

## 실제 서비스 출시 전 남은 일

기존 CR-022의 인증·성인/사진 검토 업체, PG 실제 통신/서명검증, 환불 워커·스케줄러, 운영자 화면, 계정 삭제와 정산/신고 보존 통합, 정책 검토가 필요하다. 이번 변경에서 실제 회원/결제/푸시를 생성·발송하거나 운영 SQL을 적용하지 않았다. 실제 테스트용 Supabase 계정4개는 여전히 생성하지 않았으며 안내용 합성 인물과 혼동하지 않는다.

로그인·DB/푸시의 실환경 상태는 실제 브라우저와 해당 프로젝트 설정에서 별도 확인해야 한다. 이번 브라우저 회귀 검사는 합성 세션과 로컬 상태를 사용했으며 이를 실서비스 연동 검증이라고 표현하지 않는다.
